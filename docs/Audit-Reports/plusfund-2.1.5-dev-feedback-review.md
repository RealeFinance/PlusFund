## 结论

Dev 的反馈是有价值的。它澄清了资金托管、赎回费和黑名单权限等设计意图，也显示团队准确理解了多数原始问题。2.1.5 中确实存在实质修复，并非无效整改。

但该文档同时明确写有“待执行”“待决策”“待核验”的事项，而且没有覆盖 2.1.5 复审中新发现的两个发布问题。因此它能支持“修复方向基本合理”，不能支持“所有问题已经关闭，可以上线”。

**当前结论保持：FAIL / PRODUCTION HOLD。剩余 0 Critical / 2 High / 2 Medium / 2 Low。**

两项 High 均与旧代理实际状态有关。如果逐代理证据能够证明不存在受影响资产或订单，可以将对应项标记为不适用；在证据出现前，不能仅凭人工口头确认关闭。

## 2.1.5 复审中未被反馈覆盖的问题

### A215-05 - Low：无效链下订单可永久占用 `offChainId`（已修改）

复审时发现，2.1.5 新增的 active ID 防重机制允许部分不可变字段以无效值创建，直到完成阶段才被拒绝；由于没有 amend、cancel 或 release 路径，该业务 ID 可能永久保持 active。项目方确认此问题已修改。关闭前需核对当前修改确实在占用编号前完成全部字段校验，或提供受权限控制的取消/更正机制，并补充对应验证证据。

### A215-06 - Low：发布构建输入无法复现 2.1.5

仓库中的 `standard-input.json` 仍包含旧版源码和错误的 optimizer 设置。当前生成脚本忽略 PlusFund 的 per-file override，因此即使重新生成也未必对应真实发布字节码。应从 Hardhat 实际 build-info 导出标准输入，并把 commit、编译设置、runtime bytecode/hash、存储布局及部署地址绑定在同一发布证明中。

## 请 Dev 提供的最小关闭材料

### 1. A215-01：旧代理资产与负债

对每个拟升级代理，在同一固定区块提供：

- 代理地址、当前 implementation、`assetRecipient`、`assetSender`、`serviceFeeRecipient`；
- 每种支持支付代币在代理地址上的余额；
- 未付款申购/赎回负债及其对账结果；
- 若余额非零，提供经过测试并由治理批准的迁移/取回方案；若余额为零，提供可重复查询的链上证据。

### 2. A215-02：历史订单完整性

- 升级前冻结新订单的区块和时间；
- 完整枚举 pending subscription、pending redemption 和相关链下订单，而不只是赎回计数；
- 每条订单的最终结清或迁移状态；
- 使用真实旧实现、真实旧存储布局和代表性历史状态完成 UUPS 升级演练。

### 3. A215-03：dust 队列风险

提交已选择并实现的缓解方案，例如收款方 opt-in、重要业务预留容量、可验证的 lot 合并/清理机制，或其他等效设计。测试必须覆盖：队列满、已付款 claim、释放容量、攻击者重复填充以及 100 段消费上限。

### 4. A215-04：`blacklistAdmin` 权限治理

确认 `PLUSFUND_ADMIN` 管理人员需要黑名单管理权限，这是当前业务权限设计。提供实际部署地址，并证明该地址由经批准的 Safe/Timelock 管理，包括所有者、阈值和延迟；同时解释并核实它与 `stokenAdmin` 的治理合约校验差异。该项风险针对治理配置能否按预期约束管理员，不针对 `PLUSFUND_ADMIN` 是否应有黑名单权限。

### 5. 发布验证

- 提供 A215-05 修改及验证证据；解决 A215-06 并验证升级脚本 initializer 分支；
- 在最终精确 commit 上执行完整 Hardhat/EVM 测试及 8 项审计回归；
- 对每个真实代理执行 OpenZeppelin `validateUpgrade` 和存储布局核验；
- 提交可复现 build-info、runtime bytecode/hash、代理 implementation slot、角色成员、Safe 阈值和 Timelock 延迟；
- 将“源码已修改”“测试已通过”“已部署”“生产状态已核验”分别给出证据，不应相互替代。

## 可重新评估 GO 的门槛

1. A215-01、A215-02 有逐代理证据关闭，或被可复核地证明为不适用；
2. A215-03 已实现缓解，或由有权主体书面接受且不会阻断关键 claim；
3. A215-04 权限边界收窄，或完成同等强度的治理约束与风险接受；
4. A215-05 修改经核验，A215-06 已解决，升级脚本 initializer 分支验证完成；
5. 最终发布提交通过动态测试、升级兼容、存储布局和可复现构建验证；
6. 部署后的实际代码、配置、角色和治理与审核材料一致。

在上述材料齐全前，建议继续保持 **PRODUCTION HOLD**。本复核为 AI 辅助安全审查，不替代专业第三方审计、法律意见或生产部署验收。
